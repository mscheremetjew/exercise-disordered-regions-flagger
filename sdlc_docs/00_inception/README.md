# Inception

This directory contains the information used to understand, clarify, and establish a new software project before detailed requirements, architecture, implementation, or testing begin.

The inception stage separates original evidence from the documents generated by the workflow.

## Contents

### `sources/`

Contains the original, unrefined information received about the project.

Examples include:

* Informal project requests.
* Emails from requesters or stakeholders.
* Meeting notes.
* Interview transcripts.
* Existing-system descriptions.
* Reference documents supplied by stakeholders.

Files in `sources/` are evidence. They must not be rewritten, replaced with summaries, or modified to incorporate later interpretations.

See [`sources/README.md`](sources/README.md) for the source-preservation rules.

### `clarified_project_request.md`

Contains the clarified interpretation of the original project request.

It records:

* The initial understanding of the request.
* The problem or opportunity.
* The intended outcome.
* The expected users or beneficiaries.
* The broad initial project boundary.
* Project-level constraints, dependencies, and risks.
* Clarification questions.
* Stakeholder answers and their impact.
* Contradictions or unresolved uncertainty.

**Primary skill:** `a-clarify-project-request`

### `project_context.md`

Contains the approved rationale, stakeholders, constraints, terminology, references, revision history, and initial scope, formed from the approved Clarified Project Request.

- Populated by humans, for humans, to give other contributors context about the project.
- Stable: modify it only when the project changes substantially.

**Primary skill:** `b-form-project-context`

Do not skip required approval gates.
